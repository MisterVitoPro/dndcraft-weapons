### P1-001: Ranged Weapons Missing from Creative Tab

**Problem Statement:**
Seven tiered ranged weapons (Sling, Blowgun, Hand Crossbow, Heavy Crossbow, Longbow, Musket, Pistol) are excluded from `Weapons.ALL_TIERED` and consequently not registered as tiered items or added to the creative tab. This violates Phase 4 spec §3 data completeness requirement: all 96 items (38 base specs × 3 tiers, minus 4 vanilla-mapped) must be registered and discoverable.

**Root Cause:**
- `Weapons.ALL_TIERED` filter (line 441-442 in `src/main/kotlin/com/dndweapons/catalog/Weapons.kt`) restricts ranged weapons to `RangeKind.NONE` or `RangeKind.THROWN` only
- Excludes: SLING (RangeKind.SLING), BLOWGUN (RangeKind.BLOWGUN), HAND_CROSSBOW, HEAVY_CROSSBOW, LONGBOW (RangeKind.BOW), MUSKET, PISTOL (RangeKind.FIREARM)
- Creative tab registration (lines 98-102 in `src/main/kotlin/com/dndweapons/DndWeaponsMod.kt`) iterates `ALL_TIERED`, so these weapons are never added

**Acceptance Criteria:**
1. ALL_TIERED expands to include all 34 tiered-eligible weapons (excludes only vanilla-mapped: Shortsword, Shortbow, Light Crossbow, Trident)
2. Creative tab registration adds all 102 tiered items (34 base × 3 tiers)
3. Registry contains Iron, Diamond, Netherite variants for all ranged DnD weapons
4. No duplicate registrations; all IDs remain unique

**Fix Scope:**
- **File:** `src/main/kotlin/com/dndweapons/catalog/Weapons.kt`
- **Change:** Modify ALL_TIERED filter (lines 440-442)

**Before:**
```kotlin
val ALL_TIERED: List<Pair<WeaponSpec, Tier>> = ALL
    .filter { it.vanillaRoleTag == null && it.ranged in setOf(RangeKind.NONE, RangeKind.THROWN) }
    .flatMap { base -> Tier.values().map { tier -> base.atTier(tier) to tier } }
```

**After:**
```kotlin
val ALL_TIERED: List<Pair<WeaponSpec, Tier>> = ALL
    .filter { it.vanillaRoleTag == null }
    .flatMap { base -> Tier.values().map { tier -> base.atTier(tier) to tier } }
```

### P1-003: Unsafe Translation Key Validation

**Problem Statement:**
Translation keys are constructed and passed as raw strings without validation. Malformed keys could trigger silent rendering failures at runtime.

**Root Cause:**
- TooltipLine accepts translationKey as String parameter without validation (line 10-13 in `src/main/kotlin/com/dndweapons/tooltip/TooltipLine.kt`)
- No validation that keys match the pattern `^[a-z0-9_.]+$` and refer to actual entries

**Acceptance Criteria:**
1. All translation keys validated at TooltipLine construction to match pattern `[a-z0-9_.:]+`
2. Clear error messages if validation fails

**Fix Scope:**
- **File:** `src/main/kotlin/com/dndweapons/tooltip/TooltipLine.kt`

**Before:**
```kotlin
data class TooltipLine(
    val translationKey: String,
    val args: List<Any> = emptyList(),
)
```

**After:**
```kotlin
data class TooltipLine(
    val translationKey: String,
    val args: List<Any> = emptyList(),
) {
    init {
        val pattern = Regex("^[a-z0-9_.:]+$")
        require(translationKey.isNotBlank()) { "Translation key cannot be blank" }
        require(pattern.matches(translationKey)) {
            "Invalid translation key '$translationKey': must contain only lowercase alphanumeric, dots, colons, and underscores"
        }
    }
}
```

### P1-004: Path Traversal in Wiki Filename Generation

**Problem Statement:**
Wiki filename generation does not validate that output paths remain within the intended directory. A malicious displayName containing `../` could write files outside the output directory.

**Root Cause:**
- `WikiGen` (line 40 in `src/main/kotlin/com/dndweapons/codegen/WikiGen.kt`) uses `weaponsOut.resolve(WikiPaths.weaponFilename(...))` without validating the resolved path stays within weaponsOut

**Acceptance Criteria:**
1. WikiGen validates that resolved file path remains under weaponsOut
2. Path normalization applied before validation
3. IllegalArgumentException thrown if path escapes intended directory

**Fix Scope:**
- **File:** `src/main/kotlin/com/dndweapons/codegen/WikiGen.kt` (lines 38-46)

**Before:**
```kotlin
for (spec in allSpecs) {
    val md = WikiTemplates.renderWeaponPage(spec, lookup)
    weaponsOut.resolve(WikiPaths.weaponFilename(spec.displayName)).writeText(md)
}
```

**After:**
```kotlin
for (spec in allSpecs) {
    val md = WikiTemplates.renderWeaponPage(spec, lookup)
    val filePath = weaponsOut.resolve(WikiPaths.weaponFilename(spec.displayName))
    val normalizedFile = filePath.normalize()
    val normalizedDir = weaponsOut.normalize()
    require(normalizedFile.startsWith(normalizedDir)) {
        "Path traversal detected: $filePath escapes directory $weaponsOut"
    }
    filePath.writeText(md)
}
```

### P1-005: Unvalidated String Interpolation in ResourceLocation

**Problem Statement:**
ResourceLocation.fromNamespaceAndPath() is called with spec.id and weapon lookup IDs without validating that these strings conform to Minecraft's resource location format.

**Root Cause:**
- `WeaponLookup.byId()` (line 28-30 in `src/main/kotlin/com/dndweapons/acquisition/WeaponLookup.kt`) passes weaponId directly to rl() without validation
- Invalid characters (e.g., spaces, uppercase) could cause runtime errors during registration

**Acceptance Criteria:**
1. ResourceLocation namespace and path validated to match Minecraft's pattern: `[a-z0-9_.-]+`
2. Validation occurs before ResourceLocation construction
3. Clear error messages if invalid IDs are used

**Fix Scope:**
- **File:** `src/main/kotlin/com/dndweapons/acquisition/WeaponLookup.kt` (lines 28-40)

**Before:**
```kotlin
fun byId(weaponId: String, tier: Tier): Item? {
    val targetId = weaponId + tier.suffix
    val location = rl(DndWeaponsMod.MOD_ID, targetId)
    // ...
}
```

**After:**
```kotlin
fun byId(weaponId: String, tier: Tier): Item? {
    validateResourceLocationPath(weaponId)
    val targetId = weaponId + tier.suffix
    validateResourceLocationPath(targetId)
    val location = rl(DndWeaponsMod.MOD_ID, targetId)
    // ...
}

private fun validateResourceLocationPath(path: String) {
    val pattern = Regex("^[a-z0-9_.-]+$")
    require(path.isNotBlank()) { "ResourceLocation path cannot be blank" }
    require(pattern.matches(path)) {
        "Invalid ResourceLocation path '$path': must contain only lowercase alphanumeric, dots, hyphens, and underscores"
    }
}
```

### P1-006: Identity Mappings JAR Validation Missing

**Problem Statement:**
For Minecraft 26.1.2, the build references a hardcoded path to identity-mappings-26.1.2.jar without validating that the file exists. A missing file would cause a cryptic Gradle error.

**Root Cause:**
- build.gradle.kts unconditionally references `${rootProject.projectDir}/libs/identity-mappings-26.1.2.jar` without validation
- Error messages would be vague rather than clear

**Acceptance Criteria:**
1. Build script checks that identity-mappings JAR exists before referencing it
2. Clear error message if file is missing
3. Build fails fast during Gradle initialization

**Fix Scope:**
- **File:** `build.gradle.kts` (lines 33-44)

**Before:**
```kotlin
val isMojangNamed = (property("minecraft_version") as String).startsWith("26.")

dependencies {
    // ...
    if (isMojangNamed) {
        mappings(files("${rootProject.projectDir}/libs/identity-mappings-26.1.2.jar"))
    }
    // ...
}
```

**After:**
```kotlin
val isMojangNamed = (property("minecraft_version") as String).startsWith("26.")

dependencies {
    // ...
    if (isMojangNamed) {
        val mcVersion = property("minecraft_version") as String
        val mappingsJar = rootProject.projectDir.resolve("libs/identity-mappings-$mcVersion.jar")
        require(mappingsJar.exists()) {
            "Identity mappings JAR not found: $mappingsJar\n" +
            "Please ensure it is present in the libs/ directory for MC version $mcVersion"
        }
        mappings(files(mappingsJar.absolutePath))
    }
    // ...
}
```

### P1-007: Java Toolchain Not Per-Version

**Problem Statement:**
The build.gradle.kts should validate that each version's Java requirement matches its gradle.properties setting, preventing cross-version compilation conflicts.

**Root Cause:**
- build.gradle.kts reads java_release from gradle.properties (correct) but does not validate version compatibility
- No enforcement that 1.20.1 uses JDK 17, 1.21.x uses JDK 21, 26.x uses JDK 25

**Acceptance Criteria:**
1. Java toolchain validation per Minecraft version
2. Each version's gradle.properties java_release validated against minimum requirement
3. Clear error if there is a version mismatch

**Fix Scope:**
- **File:** `build.gradle.kts` (lines 15, 21-26)

**Before:**
```kotlin
val javaRelease = (property("java_release") as String).toInt()

java {
    toolchain {
        languageVersion.set(JavaLanguageVersion.of(javaRelease))
    }
    withSourcesJar()
}
```

**After:**
```kotlin
val mcVersion = property("minecraft_version") as String
val javaRelease = (property("java_release") as String).toInt()

val minJavaForVersion = when {
    mcVersion.startsWith("26.") -> 25
    mcVersion.startsWith("1.21.") -> 21
    mcVersion.startsWith("1.20.") -> 17
    else -> error("Unknown MC version: $mcVersion")
}
require(javaRelease >= minJavaForVersion) {
    "MC $mcVersion requires Java $minJavaForVersion+, but java_release=$javaRelease"
}

java {
    toolchain {
        languageVersion.set(JavaLanguageVersion.of(javaRelease))
    }
    withSourcesJar()
}
```

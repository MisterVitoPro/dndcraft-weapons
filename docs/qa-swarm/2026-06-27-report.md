## P1 - High Priority

### [P1-001] RACE CONDITION: invalidateRoleCache() can overwrite building cache
**Corroborated by:** 1 agent (Async)  
**Confidence:** Confirmed  
**Location:** src/main/kotlin/com/dndweapons/registry/SpecRegistry.kt:66-68, 79-94  
**Severity:** P1  
**Description:** 
The `invalidateRoleCache()` method (line 66-68) is NOT synchronized. The `buildRoleCacheAndStore()` method (line 79) IS synchronized. During concurrent execution (client tooltip render + server TAGS_LOADED event), this sequence can occur:
1. Client thread acquires lock in buildRoleCacheAndStore(), starts building
2. Server thread calls invalidateRoleCache(), sets roleCache = null (unsynchronized write)
3. Client thread completes build, writes roleCache = out (overwrites invalidation)
4. Cache is now stale; next tooltip lookup reads old tag mappings

**Evidence:**
```kotlin
// Line 66-68: NOT synchronized
fun invalidateRoleCache() {
    roleCache = null
}

// Line 79-94: IS synchronized
@Synchronized
private fun buildRoleCacheAndStore(): Map<Item, WeaponSpec> {
    roleCache?.let { return it }
    val out = mutableMapOf<Item, WeaponSpec>()
    // ... build cache ...
    roleCache = out  // Writes without re-check after sync exit
    return out
}
```

Comment at P2-017 (lines 70-77) documents the intent to fix but the fix is incomplete.

**Suggested Fix:** 
Synchronize `invalidateRoleCache()`:
```kotlin
@Synchronized
fun invalidateRoleCache() {
    roleCache = null
}
```
Or add re-check in buildRoleCacheAndStore() before final write.

### [P1-004] Java toolchain version mismatch (JDK 25 globally, needs JDK 17 for 1.20.1)
**Corroborated by:** 1 agent (Config)  
**Confidence:** Confirmed  
**Location:** gradle.properties:3, build.gradle.kts:22-24  
**Severity:** P1  
**Description:** 
`gradle.java.home` is set globally to JDK 25, but per-version builds require different JDK versions:
- 1.20.1: JDK 17
- 1.21.1/1.21.4/1.21.11: JDK 21
- 26.1.2: JDK 25

The toolchain config attempts to select per-version JDK (via java_release property), but gradle.java.home global setting forces JDK 25 for all tasks.

**Evidence:**
```properties
# gradle.properties (global, wrong for all versions except 26.1.2)
org.gradle.java.home=C:/Program Files/Amazon Corretto/jdk25.0.3_9

# versions/1.20.1/gradle.properties (conflicts)
java_release=17
```

**Suggested Fix:** 
Remove `org.gradle.java.home` from gradle.properties and set per-version in versions/<mc>/gradle.properties, OR use Gradle JVM toolchain discovery.

### [P1-006] Path traversal vulnerability in wiki filename generation
**Corroborated by:** 1 agent (Security)  
**Confidence:** Likely  
**Location:** src/main/kotlin/com/dndweapons/codegen/wiki/WikiPaths.kt:18-23, WikiGen.kt:40  
**Severity:** P1  
**Description:** 
The `weaponFilename()` function converts display names to wiki filenames without validating against path traversal characters. While current weapon display names are hardcoded and safe, this violates secure-by-default principles. If a future weapon spec includes `../`, `/`, `\`, or null bytes, the generated filename could escape the intended output directory.

**Suggested Fix:** 
Validate weaponFilename input to reject characters outside `[a-zA-Z0-9 -]`.

### [P1-007] Unsafe translation key prefix validation (tooltip injection)

**Severity:** P1

The `toComponent()` function checks `arg.startsWith("tooltip.dndweapons.")` without boundary validation. A string like `"tooltip.dndweapons.hack::injection"` would pass the check.
